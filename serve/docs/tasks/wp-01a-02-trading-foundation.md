## 1. 目标与用户价值

一次完成 WP-01A 剩余基础：统一 Trading ORM 类型、20 张 foundation 表、
`v2_0002_trading_foundation`、外层 UoW 和可崩溃恢复的 Outbox。完成后，后续 Polymarket
行情、AI、决策与执行模块都能在同一事务、幂等和证据底座上施工，不再为微任务反复交接。

本里程碑分 4 个内部 checkpoint；实现者必须连续推进，checkpoint 之间不等待用户、不另建
task/manifest。只有全部通过后才写一份最终 manifest。

## 2. 已确认决策

1. V2 物理 schema 固定为 `trading`；Base 18 张旧表和 `public` schema 行为不变。
2. Alembic revision 固定 `revision="b1000002"`、`down_revision="b1000001"`；DDL 只走 Alembic。
3. PostgreSQL 是唯一事实源；Redis publish/ACK 不是业务完成证据。
4. Model 只声明字段和约束；UoW 唯一拥有 commit/rollback；Repository 不自行 commit；网络调用
   不得发生在数据库事务内。
5. 20 张表名以 §4.2 为唯一物理名称；不得产生近义平行表。
6. foundation/control/artifact/vault/outbox 记录默认 append-only；更正新增版本、history 或
   supersede 记录，禁止覆盖已发布事实。
7. 所有钱/数量使用 `NUMERIC(38,0)`/base unit，所有业务时间使用 UTC `TIMESTAMPTZ`，hash 与
   外部 ID 使用 `C` collation；禁止 float 与 naive datetime。
8. Vault 本期只建加密数据模型，不实现解密服务；数据库/API/log/Redis 中不得出现明文 secret。

## 4. 实现合同

### 4.1 Checkpoint A — ORM kernel

- `TRADING_SCHEMA = "trading"` 是唯一 schema 常量。
- type factory：`utc_timestamp_type()`、`base_unit_type()`、`sha256_type()`、
  `external_id_type()`，分别生成独立的 `TIMESTAMPTZ`、`NUMERIC(38,0)`、
  `VARCHAR(64) COLLATE "C"`、`TEXT COLLATE "C"` 实例。
- mixin：`BigIntIdentityMixin`、`CreatedAtMixin`、`TimestampMixin`、
  `OptimisticVersionMixin`；identity 为 `GENERATED BY DEFAULT`，version Python/server 初值均为 1
  并启用 SQLAlchemy optimistic locking。
- `models/trading/__init__.py` 和 `app/models/__init__.py` 只做显式 import/export；禁止动态扫描、
  I/O 或重复 metadata。

Checkpoint 验证：type/DDL/mapper/import 定向测试通过后立即进入 B，不写 manifest。

### 4.2 Checkpoint B — 20 张 foundation models

必须且只能声明下列物理表：

```text
artifact_objects
artifact_lineage_edges
archive_manifests
retention_manifests
runtime_config_versions
strategy_objective_contracts
strategy_versions
model_role_bindings
execution_spec_versions
capital_permission_manifests
release_manifests
policy_type_scopes
policy_freezes
secret_vault_entries
secret_vault_versions
secret_access_events
idempotency_claims
transactional_outbox
outbox_delivery_history
job_completions
```

固定字段/约束族：

- 每表使用 schema-qualified BIGINT identity PK；外键默认 `RESTRICT`，仅纯 lineage/history
  junction 可 `CASCADE`。
- `artifact_objects` 必须无损表达现有 `ArtifactRef`：sha256、original/stored size、mime、
  compression、storage driver/version、locator；唯一键为
  `(sha256, compression, storage_driver, storage_version)`，尺寸非负，raw 时两尺寸相等。
- `artifact_lineage_edges` 保存 from/to artifact、受控 relation、可空 invocation ref、created_at；
  禁止 self-edge，重复 edge 由唯一约束拒绝。
- archive/retention manifest 保存 canonical JSONB、content hash、状态与 created_at；已 committed
  内容不可更新。
- control 对象保存 canonical JSONB/schema version/content hash/status/creator/time；
  `model_role_bindings` 在同一 strategy version 内 role 唯一；`release_manifests` 必须 FK 固定
  config/strategy/execution/permission 版本并保存 git SHA、image digest、DB revision、总 hash；
  激活记录不得依赖“latest”。
- `capital_permission_manifests` 分开 evaluation capital 与 authorized capital，保存 mode、
  capability、limits、kill-switch；两种资本均为非负 base unit。
- `policy_type_scopes` 对 `(policy_type, scope_type, scope_key)` 唯一；`policy_freezes` 引用精确
  policy content hash/release，不读运行中 latest。
- Vault entry 是稳定 identity；version 只保存 key id/version、nonce、ciphertext、AAD hash、
  algorithm、created_at/supersedes，不得出现 plaintext/value/token/password 字段；
  access event append-only，保存主体、用途、结果 reason code 和时间，不保存 secret 内容。
- `idempotency_claims(scope,key)` 全局唯一，并保存 owner、created_at；不得放进分区表。
- `transactional_outbox` 至少保存 event id、topic、schema version、aggregate identity、
  idempotency key、release manifest、priority、payload JSONB 或 artifact（二者恰一）、status、
  attempt、available/deadline/visibility、lease owner/token、错误 reason code 与时间；event id 唯一，
  `(available_at,id) WHERE status='PENDING'` 必须有 partial index。
- `outbox_delivery_history` 是按 `completed_at` 月 RANGE 分区且无 default partition的
  append-only terminal history；分区唯一键必须包含 `completed_at`。revision 创建升级当月及后两月
  分区；`job_completions` 对 `(consumer, idempotency_key)` 唯一。完成/归档必须能追溯原 outbox
  event。
- 状态/关系使用受控 `CHECK` + text，不创建 PostgreSQL ENUM；JSONB 必须是 object 的字段增加
  `jsonb_typeof(...)='object'` CHECK；所有 constraint/index 显式稳定命名。

Checkpoint 验证：20 表 metadata 集合、FK/unique/check/index 和 PostgreSQL DDL golden 测试通过后
立即进入 C。

### 4.3 Checkpoint C — `v2_0002` migration

- `upgrade` 创建 `trading` schema 和上述 20 张表；不得调用 `Base.metadata.create_all()`，不得修改
  `public` Base 对象、seed、menu 或 legacy runner。
- `downgrade` 仅按依赖逆序删除这 20 张表和空的 `trading` schema；非空/未知对象时 fail-closed，
  不用 `CASCADE`。
- migration 遵守现有单 run 外层事务、advisory lock、search path 和 offline SQL 合同。
- 真 PostgreSQL 同时覆盖 literal-empty 与 existing-Base fixture：
  `b1000001 → b1000002 → b1000001 → b1000002`；shape/data/sequence 保持，失败整 run 回滚。
- Alembic metadata compare 在 `trading` schema 对 type/default/nullability/FK/UNIQUE/CHECK/index
  drift 为 0；heads 只有 `b1000002`。

### 4.4 Checkpoint D — UoW 与可靠 Outbox

- `UnitOfWork` 接收 async session factory；`async with` 唯一 begin/commit/rollback/close；body 或
  commit 异常 rollback，禁止嵌套静默 commit。after-commit hook 只在 commit 成功后运行；hook
  失败不得伪装 DB rollback，也不得用于外部投递定案。
- versioned envelope 必须校验 topic/schema/idempotency/release/deadline/priority/payload；canonical
  序列化稳定；原始 secret、任意 Python object 和 float 拒绝。
- Repository 所有写方法接收现有 session/UoW，绝不 commit；enqueue 与业务事实同一事务；claim
  使用 `FOR UPDATE SKIP LOCKED`；状态转换以 expected state/lease token/fencing 条件更新，受影响
  行数不为 1 即固定 conflict reason。
- Publisher：短事务 claim → commit → Redis Stream publish → 新事务标 `DISPATCHED`；publish
  超时/异常保持可恢复状态，不能写 completion。不得在持锁事务中做网络调用。
- `redis_control.py` 仅补 publisher/consumer 必需的 consumer-group create/read/ack/pending/claim
  原语；继续使用现有 namespace 和 fail-closed 语义，不得加入 Outbox 业务状态判断。
- Consumer：按 owner/lease/fencing 调 Handler；先检查 `job_completions`，重复投递不得产生第二次
  effect；成功时在一个事务内写 completion、delivery history，并从 hot outbox 收敛；失败按冻结
  retry policy requeue/dead，不吞异常。
- Sweeper：只认领 visibility 已过期且未 completion 的行；原子重投并递增 attempt；到上限写
  terminal history；未知状态 fail-closed，不删除。
- 测试必须证明：业务写+enqueue 原子性、两个 publisher 不重复 claim、publish 前/后 crash、
  ACK 丢失、consumer crash、重复 delivery、lease 过期、stale fencing、handler 成功/失败、
  completion/history 原子性以及最终重复经济 effect=0。
