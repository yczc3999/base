**日期**：2026-08-04
**范围**：后端核心管道 / 控制器与路由 / 模型与数据库 / 服务层与任务队列 / 前端 全量评审
**方法**：主会话亲读核心管道（`logics/base.py` 542 行 / `controllers/base.py` 260 行 / `config.py`）+ 5 个并行分域精读代理；关键发现多处独立互证。

## 1. 安全发现（P0，按优先序）

### S1. 🔴 Mass-assignment 越权提权（CRITICAL）
- **位置**：`controllers/base.py:153` `_do_edit` 全量透传；`logics/base.py:263` `self.model(**data)`；全站无任何 logic 覆写 `format_save_data`（grep 仅 base.py 命中，`logics/base.py:364`）
- **描述**：CRUD 层对客户端传入字段零白名单。拥有 `admin:user:edit` 权限的普通管理员可 POST `{"id":1,"is_super_admin":true}` 自提超级管理员；同样可改写 `token_version` 等任何模型列。直接违反「白名单>黑名单」哲学底线。
- **附带**：未知字段（非模型列）抛 TypeError→500，且 `:263` 在 try 块之外，请求带 `{"foo":1}` 直接 500。
- **修复**：给 `BaseLogic` 增加可写字段白名单机制（默认仅保留模型列，剔除 pk/审计列），子类声明；或强制子类实现 `format_save_data` 做字段白名单。

### S2. 🔴 `/setting/get` 无权限返回全部明文密钥（CRITICAL）
- **位置**：`controllers/admin/setting.py:20-23`（get 无 perms）；`logics/setting.py:25-37`（`settings:all` 全量缓存 300s 且 Redis 明文）；密钥存于 `services/ai.py:33`（`ai.api_key`）、`services/seo_gsc.py:21` / `seo_bing.py:18` / `seo_indexnow.py:30`（`seo_creds.*`）
- **描述**：任何非超管管理员可读取并改写 AI / IndexNow / GSC / Bing 全部密钥与系统配置。凭据本身明文存 settings 表（`services/base.py:86-94`），`config.py:9/19/28` 的 `APP_KEY`/`DATABASE_PASSWORD`/`REDIS_PASSWORD` 均为普通 `str` 而非 `SecretStr`。
- **修复**：`/setting/get` 对非超管过滤敏感 category；`/setting/set` 挂 `require_perms("admin:setting:set")`；关键凭据改 `SecretStr` / 金库加密；缓存脱敏或分 key。

### S3. 🔴 上传无 MIME 白名单 → 存储型 XSS（HIGH）
- **位置**：`controllers/admin/file.py:23-41`（通用 upload 不传 `allowed_types`=None 跳过校验）；`ALLOWED_FILE_TYPES` 在 `file.py:7` import 但从未使用；`main.py:88` `/uploads` 静态挂载
- **描述**：`.html`/`.svg` 上传后经 `/uploads` 直出 → 存储型 XSS / 任意文件托管。
- **修复**：默认路由也传入 `ALLOWED_FILE_TYPES`，并加内容嗅探校验。

### S4. 🟠 IDOR 三连
- **S4a 编辑无归属校验**：crud_router 文档声称 bind_user_column 覆盖 getList/getDetail/doEdit/doDelete，但 `_do_edit`（`controllers/base.py:153-174`）更新路径不校验记录归属（`:168` 仅 create 时注入 user_id；getDetail `:136` 与 doDelete `:208` 都校验了，唯独编辑漏）→ 非超管可改他人数据（message/file 均配了 bind_user_column）。
- **S4b `/file/batchDelete` 绕过归属**：`controllers/admin/file.py:67-82` 直接调 `file_logic.delete_files(db, ids)` 无 user_id 过滤，与 crud_router doDelete 的归属校验（`base.py:207-212`）权限模型不一致。
- **S4c export 无视归属**：`_do_export`（`base.py:239-257`）user_id 只用于生成 key，job payload 无归属信息，`do_export` 查询不带 `bind_user_column` → 绑归属模块一旦开启导出即泄露全量数据。
- **修复**：modify 的 WHERE 追加 `bind_user_column == user_id`；`delete_files` 增加 user_id 参数并过滤；user_id/is_super 传入 do_export 供 ExportHelper 查询追加归属条件。

### S5. 🟠 会话安全
- **登出不撤销 refresh_token**：`token.py:151-171` + `admin/user.py:134` + `client/user.py:94` —— 只删 access_token，refresh_token 及其索引 `user_refreshes:*` 未删，7 天内仍可换新。
- **refresh_token 不轮换、无重用检测**：`token.py:102-148` —— 同一 refresh_token 多次刷新始终有效，被盗可反复换新。
- **client 登录/注册无限流**：`client/user.py:34-71` 无速率限制（admin 端 `admin/user.py:52-54` 有 5 分钟 10 次限流）。
- **修复**：登出按 `_user_refreshes_key` 索引删除全部 refresh；refresh 时轮换 + 重用检测；client 复用 `check_rate_limit`。

### S6. 🟡 其余安全
- `allowed_filters()` 默认 None = 全列可过滤（`logics/base.py:61-63`）→ 敏感列可作过滤面 / 时序侧信道。**修复**：默认给显式白名单（pk + created_at/updated_at）。
- keyword / 过滤值通配符注入：`query.py:200-212,244-251,302-305` 的 `ilike(f"%{value}%")` 中 `%`/`_` 未转义，`%` 可放大成全表匹配（非 SQL 注入）。**修复**：转义或限制 keyword 长度。
- `bind_user_column` 列名写错时静默失配（`logics/base.py:138-140`）→ 配置错误即越权且无告警。**修复**：列不存在时抛配置异常。
- 分页 page 无上限 → offset 无限深扫（`logics/base.py:116-122,160`）。**修复**：加 page 上限或 keyset 分页。
- 敏感数据入 Redis：`get_by_field`/`get_detail` 用 `with_sensitive=True` 缓存**含 password hash** 的完整 dict（`logics/base.py:227,248`）。**修复**：敏感字段不落缓存或分表。
